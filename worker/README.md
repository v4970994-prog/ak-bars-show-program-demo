# Рабочее приложение V34.7

Исходник Cloudflare Worker: `src/worker.js`.
Сборка: `AB_SHOW_V34_7_GROUP_APPROVAL_20261008`.

Это полноценное приложение с авторизацией Telegram/MAX и браузерным входом, общей базой D1, расчётами и согласованиями. Статическое демо в корне репозитория существует отдельно. GitHub Pages не исполняет этот Worker.

## Изменения V34

- Ответственный от ООО «Мега Шоу» на каждом сохранённом событии. Кнопка «Ответственный» находится в календаре на карточке события.
- Выбор только из активных менеджеров и исполнителей подрядчика. Назначать могут координаторы, автор мероприятия с ролью сотрудника СКП и менеджеры подрядчика. Назначение не даёт новых прав согласования.
- Назначение, смена даты/места/вводных и удаление события уведомляют ответственного. При переназначении прежний участник получает сообщение о снятии назначения.
- Финальное согласование: одно сообщение на участника из объединённого списка автора, менеджеров подрядчика и ответственного; автор-согласующий исключается как и прежде. Сохраняются выбранный канал и связанные аккаунты.
- Сообщение содержит мероприятие, дату/время по Москве, место, адрес и контакт, а согласование также сумму, автора и согласовавшего. Ссылка ведёт в календарь к событию; «Расчёты» открывает его расчёты и их состав.
- В D1 добавляются поле `events.responsible_user_id` и журнал `event_assignment_history`. Существующие события остаются без назначенного ответственного до ручного выбора. Данные не очищаются.
- Тёплая светлая и тёмная темы, сохранение выбора, системный читаемый шрифт вместо встроенных Q10/TT Octo, полупрозрачные панели, состояния наведения/касания/фокуса. Анимация отключается при `prefers-reduced-motion`.
- Календарь при ширине от 1100 px - месяц Пн-Вс с выбором дня. На телефоне - хронологический список по месяцам. Все карточки действий кликабельны целиком.
- Дизайн адаптирован по `DESIGN_DIRECTION.md` и REF-001..004 из папки проекта UX/UI; рекламный модуль и правила согласования не меняются.

Проверка браузера: `npm run test:ui` при установленном Playwright/Chromium. Можно задать `CHROMIUM_EXECUTABLE` и `UI_SCREENSHOTS`. Используются только вымышленные данные и локальные ответы API. Настоящая доставка в Telegram/MAX проверяется отдельно действием пользователя: автоматические тесты не отправляют сообщения.

## Сохранённые изменения V33.3

- Предпросмотр Excel до записи в базу: исправление карточек, удаление лишних строк, проверка обязательных полей, пропуск повторов.
- Удаление других мероприятий по одному или выбранной группой. Связанные неудалённые расчёты блокируют удаление всей группы.
- Изменение даты, времени и реквизитов матчей и мероприятий. ID и связи с расчётами сохраняются. Спецификация учитывает новый месяц.
- Проверка прав на сервере и защита карточек от перезаписи устаревшими данными.
- Сохранены изменения V33.1 (создание расчётов менеджером подрядчика) и V33.2 (другие мероприятия в месячной спецификации).

При подготовке публичного исходника удалён только неиспользуемый `APP_DATA.services` со старыми ценами. Приложение получает актуальный каталог из D1. Оригинальный TXT V33.3 хранится отдельно. Встроенный календарь оставлен для поддержки старых ссылок на матчи.

## Проверка

Node.js 24 или новее, внешние зависимости не требуются:

```sh
cd worker
npm test
```

Тест запускает реальный Worker с тестовой авторизацией и SQLite в памяти. Он проверяет миграции, импорт, повторы, удаление, права, защиту связанных расчётов и перенос матчей между месяцами. Данные в тесте вымышленные. Рабочая база не используется.

## Публикация в существующий Cloudflare Worker

Цель: существующий `ak-bars-show-program`. Использовать его текущую базу D1 и секреты. Не создавать новый сезон и не создавать новую базу.

1. В Cloudflare откройте текущий Worker. В разделе Bindings проверьте привязку `DB` и запишите имя и ID связанной базы D1.
2. В Settings -> Builds -> Connect подключите этот репозиторий, ветку `main`, корневую папку `worker`.
3. Задайте build variables `CLOUDFLARE_D1_DATABASE_ID` и `CLOUDFLARE_D1_DATABASE_NAME` из существующей привязки, а также `NODE_VERSION=24`.
4. Build command: `npm test && npm run configure`.
5. Deploy command: `npx wrangler deploy --config wrangler.json`.
6. Первый запуск выполняйте после проверки, что выбран существующий Worker. После развёртывания проверьте вход, наличие сезона и мероприятий, предпросмотр Excel и изменение тестового события.

Скрипт configure не создаёт базу и останавливает сборку, если её реквизиты не указаны. `keep_vars` сохраняет переменные из кабинета Cloudflare. Секреты Telegram/MAX остаются в настройках существующего Worker. До первого подключения нужно также сверить остальные bindings и параметры текущего Worker; дополнительные привязки, если они есть, добавить в конфигурацию перед деплоем.

Существующие настройки приложения: `TELEGRAM_BOT_TOKEN`, `MAX_BOT_TOKEN`, `ALLOWED_TELEGRAM_IDS`, `ALLOWED_MAX_IDS`, при наличии `WEB_AUTH_SECRET`. Значения не хранить в репозитории. Названия перечислены для сверки, не для пересоздания.

Быстрый ручной вариант: целиком вставить `src/worker.js` в Edit code текущего Worker и выполнить Save and Deploy. Это обновляет код через существующие настройки в кабинете.

Сам push на GitHub до подключения Workers Builds не обновляет рабочий сайт. Старое статическое демо GitHub Pages не является подтверждением развёртывания V33.3.

Документация:
- https://developers.cloudflare.com/workers/ci-cd/builds/
- https://developers.cloudflare.com/workers/ci-cd/builds/configuration/
- https://developers.cloudflare.com/workers/wrangler/configuration/

Важно: настройки Builds нужно сохранить до следующего push. Для этого приложения корневая папка сборки — `/worker`; публикация из корня репозитория может развернуть статическое демо вместо рабочего приложения.

## V34.1: категории и стоимость прошедших мероприятий

- Категория расчёта определяется по связанному мероприятию. Старое значение `ak-bars` у нематчевых расчётов исправляется при чтении без перезаписи сумм и истории. Новые расчёты сохраняют корректную команду, редактирование обновляет её.
- На главной для customer owner/coordinator/executive добавлена общая стоимость текущего сезона: стандартная часть прошедших матчей (по той же действующей смете, что в спецификациях) + согласованные расчёты прошедших мероприятий. Разбивка по трём командам и другим мероприятиям, затем по событию и составу расчётов.
- Критерий прошедшего события: дата/время начала не позднее текущего момента по Москве. При неизвестном времени событие учитывается после конца дня. Это расчётная стоимость, не факт оплаты или подтверждение завершения. Стандартная часть не зафиксирована исторически и меняется с действующей сметой, как в существующих спецификациях.
- Будущие/удалённые события, удалённые и несогласованные расчёты исключаются. Данные других сезонов не загружаются в сводку.
- `secrets.required` требует `TELEGRAM_BOT_TOKEN` и `MAX_BOT_TOKEN` перед успешной публикацией. Значения не входят в репозиторий. Проверка наличия не проверяет действительность токенов у Telegram/MAX.

Если Mini App сообщает «Токен … не настроен», активная версия Worker не получает соответствующее значение. В текущем Worker откройте Settings → Variables and Secrets (именно настройки Worker, не Build variables), добавьте оба существующих токена как Secret и выполните Deploy. Если запись уже есть, проверьте, что версия с ней активна. После восстановления повторите неуспешную сборку V34.1. Никогда не вставляйте токены в код, git или чат.

Проверки: `npm test` включает регрессии категорий и сводки. `npm run test:ui` проверяет фильтры и переход по сводке в Chromium с вымышленными данными. Внешняя отправка сообщений и рабочая база этими тестами не затрагиваются.

## V34.3: мобильные формы

- Назначение ответственного: список радиокнопок внутри приложения, имя и роль отдельно, светлая/тёмная тема. Сохраняются прежний endpoint, права, revision и уведомления.
- Поля `time` в предпросмотре импорта и редакторе событий отображаются как часы и минуты, без системного popup. Исходное поле сохраняет значение HH:mm и события input/change для существующей валидации.
- VisualViewport resize/scroll и фокус запускают прокрутку поля внутри страницы или модального окна. При клавиатуре окно ограничивается видимой высотой, нижняя навигация скрывается. Pinch zoom не принимается за клавиатуру.
- Цвета темы меняются за 300 мс; начальная загрузка без анимации, prefers-reduced-motion соблюдается.
- Chromium: проверены сохранение назначения, формат времени, видимость полей на странице и внутри модалки при моделировании высоты VisualViewport, возврат после клавиатуры, анимация и reduced motion. Физическая клавиатура Android/iOS и оболочки MAX/Telegram требуют проверки на устройстве.

## V34.6: ответы на возврат и мероприятия группы

У автора возвращённого расчёта есть кнопка «Ответить на комментарий». Ответ сохраняется в истории, причина возврата остаётся видна. Можно оставить расчёт на доработке или ответить и повторно отправить его по существующему маршруту согласования. Ответ без повторной отправки уведомляет только вернувшего согласующего; повторная отправка также уведомляет текущего согласующего без дублирования получателей. Выбор Telegram/MAX берётся из профиля. Ошибка доставки не отменяет сохранённый ответ.

В карточке расчёта, на согласовании и в составе отображаются все мероприятия его группы с датами, временем, местом, суммами и статусами. Подсвечен текущий расчёт. Согласование и ответ относятся только к нему. В уведомлениях есть сведения о группе и ссылка на конкретный расчёт.

Миграция добавляет `request_key` в существующую историю и уникальный индекс для повторных запросов. Существующие комментарии и расчёты сохраняются. `npm test` проверяет права, маршруты, гонки, повторные запросы, сбой доставки и состав группы на SQLite. `npm run test:ui` дополнительно проверяет ответ, повторную отправку, экран согласующего и мобильную вёрстку в Chromium. В проверках используются только локальные данные и заглушки доставки.


## V34.7: один расчёт и одно согласование на группу мероприятий

- В «Расчётах» и «Согласованиях» одна карточка на группу `batch_group` одного автора в одном сезоне. Старые группы отображаются так автоматически. Совпадение названий само по себе не объединяет расчёты.
- Список дат, времени, мест, сумм и статусов раскрывается кнопкой «Посмотреть мероприятия». Общая сумма и стоимость одного мероприятия подписаны отдельно. Одинаковый состав показан один раз; разные составы доступны по мероприятиям.
- Отправка, каждый этап согласования, возврат и ответ действуют на всю ожидающую решения часть группы. Сохраняются маршруты Виль -> Глеб, Глеб -> Виль и сотрудник/менеджер подрядчика -> Виль -> Глеб. Новое событие группы не обходит первый этап.
- В старых группах ранее согласованные строки сохраняют свои решения. Если есть черновики или возвраты, автор отправляет оставшуюся часть общим действием. Отменённые и удалённые строки не согласовываются повторно.
- Групповое редактирование меняет весь редактируемый состав. Владелец может отдельно изменить факт уже согласованного мероприятия или исключить только его через раскрытый список. Удаление общего расчёта явно указывает количество мероприятий.
- В базе по-прежнему хранится сумма на каждое событие: месячные спецификации и стоимость прошедших мероприятий не умножают общий итог повторно. Excel общего расчёта содержит список событий и отдельные листы с составом каждого; месячная выгрузка сохраняет прежний формат.
- Создание группы, изменение состава и решения выполняются атомарно. Новая таблица `calculation_operations` защищает от повторной отправки после потери ответа. В ней сохраняются только деловые поля запроса, без токенов входа. Устаревший состав/статус/список мероприятий требует обновить страницу. Старый клиент не может незаметно согласовать всю группу действием над одной строкой.
- Уведомления отправляются один раз на получателя для общего действия. Итоговое сообщение получают автор, менеджеры подрядчика и ответственные от подрядчика без повторов. Выбор Telegram/MAX остаётся прежним.

Проверка `npm test` включает девять старых мероприятий, все маршруты, общие возвраты/ответы/редактирование, повторы, конфликт версий и состава группы, откат при сбое записи, частично согласованные группы, права, отдельное исключение события и сохранность сумм. `npm run test:ui` проверяет одну карточку, скрытый список, одно нажатие согласования для девяти мероприятий, мобильный экран, месячную спецификацию и полный Excel группы. Рабочая база и настоящая доставка в этих тестах не используются.
